# DeepTutor 接入：架构与启动

> 分支：`self-learn` 与 `cross-new` 的 `deeptutor`（从各自原分支拉出）
> 对应 DeepTutor 版本：v1.6.8（协议 `protocol_version: "2.0"`）
> 最后更新：2026-09-20 05:10

## 1. 一句话

self-learn（自习室 UI 包）通过 DeepTutor 的 WebSocket 回合协议获得真实 AI 回复；`npm run dev` 会顺带把 DeepTutor 后端拉起来。DeepTutor 不可用时，聊天回落到原来的 `/api/chat`（OneHub）通道。

## 2. 结构

```
浏览器（cross-new :3000，里面渲染 @cross/self-learn）
   │  WebSocket  ws://127.0.0.1:8001/ws     （本地原型：浏览器直连）
   │  HTTP       http://127.0.0.1:8001/...
   ▼
DeepTutor 后端（Python，:8001）──> 大模型 / embedding / 知识库 / 会话库
```

- **仓库关系**：`cross-new` 是宿主主仓库，`self-learn` 是它 workspace 下的一个包（`workspace:*` 软链）。self-learn 自己没有 `app/` 和 `next.config`，不能独立运行。
- **代码落点**
  - `self-learn/src/deeptutor/`：协议契约、传输层、对话控制器、配置（见《移植记录》）
  - `self-learn/src/components/SelfStudyWorkbench.tsx`：`sendViaDeepTutor`、`stopGenerating`
  - `cross-new/scripts/dev-with-deeptutor.mjs`：一键启动器
- **本地原型的取舍**：浏览器直连后端。DeepTutor 单用户模式没有认证，任何能访问 8001 的人都是管理员，所以**这个形态不能对外暴露**；上线前需要加服务端转发层（见《决策记录》决策 1）。

## 3. 一键启动

```bash
cd packages/cross-new
npm run dev          # 启动器：DeepTutor 后端 + next dev
npm run dev:next     # 只起 next dev（原来的行为）
```

启动器（`scripts/dev-with-deeptutor.mjs`）逻辑：

| 情况 | 行为 |
|---|---|
| `DEEPTUTOR_PORT`（默认 8001）上已有 DeepTutor | 直接复用，退出时**不会**杀掉它 |
| 没有，且 `DEEPTUTOR_DIR` 下有 `.venv/bin/deeptutor` | 执行 `deeptutor serve --host 127.0.0.1 --port 8001`，轮询 `GET /` 直到就绪（最长 90 秒，实测约 5 秒），退出时一起结束 |
| DeepTutor 目录或 venv 不存在 | 只打警告，`next dev` 照常启动（聊天回落到 OneHub） |
| `DEEPTUTOR_SKIP=1` | 完全跳过后端 |

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DEEPTUTOR_DIR` | `../../../DeepTutor`（相对 `cross-new`，即与 `cross-workspace` 同级） | DeepTutor 仓库位置 |
| `DEEPTUTOR_PORT` | `8001` | 后端端口 |
| `DEEPTUTOR_HOST` | `127.0.0.1` | 绑定地址。**不要改成 0.0.0.0**（无认证） |
| `DEEPTUTOR_SKIP` | 空 | `1` 跳过后端 |
| `NEXT_PUBLIC_DEEPTUTOR_BASE` | 启动器自动设为 `http://<host>:<port>` | 浏览器访问后端的地址。**构建期常量**，改了要重启 dev |

> 注意：如果你是用 `deeptutor start`（同时带 DeepTutor 自己的前端）启动的后端，它绑定的是 `0.0.0.0`。启动器只是复用它，不会改动。

## 4. DeepTutor 侧的配置（一次性）

DeepTutor 只认 `data/user/settings/model_catalog.json` 里的大模型 / embedding 配置，**忽略 `.env`**，也没有环境变量能预置。可以在 DeepTutor 自己的设置页配，或直接改该 JSON。本机现状：大模型 OneHub（`deepseek-v4-pro` 等），embedding 用 Ollama `nomic-embed-text`。

密钥只放在这个文件里，**不要拷进任何会提交到 GitHub 的位置**。

## 5. 常见故障

| 现象 | 原因与处理 |
|---|---|
| 聊天回复很慢（首字要 5–10 秒） | 当前模型带推理，先输出思考再输出正文。属于正常 |
| 聊天回复是老的 OneHub 通道风格 | `GET /health/ready` 没通过，回落了。看浏览器控制台 `[deeptutor] isDeepTutorReady = false`，检查后端是否在 8001 运行 |
| 控制台 `protocol_error start_turn_rejected` | 同一会话上一轮还没结束（同一会话同时只允许一个进行中的回合）。等它结束或点停止 |
| WebSocket 连不上 | 确认地址是 `ws://127.0.0.1:8001/ws`（不是旧的 `/api/v1/ws`，v1 前缀已被移除） |
| 后端刚重启，旧会话续聊 | 服务端遇到未知 `session_id` 会新建会话并在 `session` 事件里返回新 id，前端会自动更新 |
| 停止生成后界面卡住 | 5 秒内服务端没确认取消时，前端会断开连接兜底 |
| 没有「模型思考」卡片 | 卡片只在服务端发了 `thinking` 事件时出现。当前模型（deepseek-v4-pro）不是每次都推理：实测「1+1」有 12 片，其它几个问题一片也没有。不是前端丢数据 |
| 取消后再提问，模型好像在回答上一个被取消的问题 | 被取消的回合，用户那句话仍留在会话历史里，模型会看到两条连续的用户消息。属于 DeepTutor 的行为 |
| 刷新后聊天变成只剩欢迎语 | 已修复。原因是原有代码：欢迎语 effect 在历史 hydrate 之前执行并覆盖了历史。现在会先看 localStorage 里有没有该空间的历史 |
| 测试会话删不干净 | `DELETE /api/sessions/{id}` 只是移进回收站；要彻底删除还要 `DELETE /api/sessions/{id}/purge`（且只能作用于回收站里的会话，所以要先软删除再 purge） |
