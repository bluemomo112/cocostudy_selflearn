## 决策 1：浏览器如何连到 DeepTutor

- **背景**：DeepTutor 单用户模式没有认证，CORS 放开，且 v1.4.2 曾在设置接口明文返回大模型 API Key（v1.6.8 已打码为 `***`）。
- **可选项**：甲，浏览器直连；乙，`cross-new` 服务端转发（Route Handler 内用 WebSocket 连 DeepTutor，对浏览器转成 SSE，只放行白名单路径）。
- **选择：甲（本地原型）**。你明确说明当前只在本地看、明文只要不进 GitHub 就行。直连让事件原样到达，断线续流、`command_ack` 这些现成能力可以直接用。
- **代价与重新评估**：直连形态不能对外暴露。传输层已隔离（`src/deeptutor/transport` + `config.ts` 的 `deeptutorWsUrl`），要上线时加转发层只需换传输实现。
- 补充：Next 的 Route Handler 不能直接接收 WebSocket，转发方案里浏览器侧只能用 SSE + POST。

## 决策 2：一条命令启动

- **选择**：改 `cross-new` 的 `dev` 脚本为启动器，保留 `dev:next`。
- **理由**：你要求"启动项目时后端也 host 起来，避免操作两次"。启动器复用已有后端、失败降级，不会拖累没装 Python 的同事。
- **为什么不是 `predev`**：它只适合一次性检查，不适合常驻进程。
- **为什么放 `cross-new` 而不是 `self-learn`**：self-learn 是被消费的库，本身跑不起来；把 Python 进程绑进库会污染它。

## 决策 3：DeepTutor 的数据目录

- **选择**：直接用 DeepTutor 自带目录（不设 `DEEPTUTOR_HOME`）。
- **理由**：本地原型，大模型 / embedding / 知识库配置都是现成的。
- **代价**：测试对话会进你 DeepTutor 的会话历史。开发中用 API 造的测试会话我会用 `DELETE /api/sessions/{id}` 清掉。
- **想隔离时**：设 `DEEPTUTOR_HOME` 指向别的目录（必须在进程启动前设置），并预置一份 `model_catalog.json`。

## 决策 4：包管理用 pnpm

- **背景**：仓库规则写 npm，但 `cross-new` 依赖 `@cross/self-learn: workspace:*`，npm 装包会报 `EUNSUPPORTEDPROTOCOL`；根目录有 `pnpm-workspace.yaml` 与 `pnpm-lock.yaml`，`self-learn/node_modules` 本来就是 pnpm 的软链结构。
- **选择**：在 `self-learn` 下用 `pnpm add`。

## 决策 5：协议类型直接复制，不手写

- **背景**：v1.6.8 起 DeepTutor 前端的协议类型由后端 JSON Schema 生成（`contracts/generated/turn-protocol.ts`），并有配套解析器和传输层。
- **选择**：整套复制到 `src/deeptutor/`，只改 import 路径和两处小扩展（见《移植记录》）。
- **理由**：字段级协议很细（`extra="forbid"`，多一个字段就被拒），手写容易错；传输层的 seq 缺口缓冲、断线续流、命令幂等是现成的。
- **升级 DeepTutor 时**：重新复制这几个文件，注意对比两处本地改动。

## 决策 6：课程 / 掌握度路径怎么用（**待你确认**）

- **背景**：DeepTutor v1.6 新增了两块和"自习空间"很贴的能力：
  - **Course**：科目容器，含 `instructions`、`default_persona`、大纲、挂载知识库；对话带 `course_id` 会自动继承。
  - **Mastery Path**：确定性的掌握度判定（出题 → 判分 → 掌握度门 → 间隔复习 → 学习地图），这是"chat + 知识库"做不到的。
  - 两者都不区分老师和学生，也没有老师查看学生掌握度的接口；同一条路径同一时间只能有一个会改状态的回合。
- **可选项**：
  - **A. 只用 chat + 知识库**，掌握度、出题、判分由我们自己实现。
  - **B. Course + KB 作为老师配置的空间，每个学生一条 Mastery Path（由同一份模板大纲复制）**，进度隔离，映射关系 `(空间, 学生) → course_id / path_id / session_ids` 存在我们自己这边。
- **建议**：B，分两步走：先做 chat + 知识库 + 富消息 UI（不管选哪条都要），再接掌握度。
- **B 缺什么**（要自习室自己补）：教师端班级视图、老师可配的门阈值（后端写死 0.9，只能靠 `override`）、模板分发、多学生聚合统计。
