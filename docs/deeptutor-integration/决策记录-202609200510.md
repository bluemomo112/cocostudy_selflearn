## 决策 1：浏览器如何连到 DeepTutor

- **背景**：DeepTutor 单用户模式没有认证，CORS 放开，且 v1.4.2 曾在设置接口明文返回大模型 API Key（v1.6.8 已打码为 `***`）。
- **可选项**：甲，浏览器直连；乙，`cross-new` 服务端转发（Route Handler 内用 WebSocket 连 DeepTutor，对浏览器转成 SSE，只放行白名单路径）。
- **选择：甲（本地原型）**。你明确说明当前只在本地看、明文只要不进 GitHub 就行。直连让事件原样到达，断线续流、`command_ack` 这些现成能力可以直接用。
- **代价与重新评估**：直连形态不能对外暴露。传输层已隔离（`src/deeptutor/transport` + `config.ts` 的 `deeptutorWsUrl`），要上线时加转发层只需换传输实现。
- 补充：Next 的 Route Handler 不能直接接收 WebSocket，转发方案里浏览器侧只能用 SSE + POST。

## 决策 2：一条命令启动

- **选择**：改 `cross-new` 的 `dev` 脚本为启动器，保留 `dev:next`。
- **理由**：你要求"启动项目时后端也 host 起来，避免操作两次"。启动器复用已有后端、失败降级，不会拖累没装 Python 的同事。
- **为什么不是 `predev`**：它只适合一次性检查，不适合常驻进程。
- **为什么放 `cross-new` 而不是 `self-learn`**：self-learn 是被消费的库，本身跑不起来；把 Python 进程绑进库会污染它。

## 决策 3：DeepTutor 的数据目录

- **选择**：直接用 DeepTutor 自带目录（不设 `DEEPTUTOR_HOME`）。
- **理由**：本地原型，大模型 / embedding / 知识库配置都是现成的。
- **代价**：测试对话会进你 DeepTutor 的会话历史。开发中造的测试会话用 `DELETE /api/sessions/{id}` 再 `DELETE /api/sessions/{id}/purge` 清掉（只做第一步是移进回收站，会话和历史仍在，并且仍能被续聊）。
- **想隔离时**：设 `DEEPTUTOR_HOME` 指向别的目录（必须在进程启动前设置），并预置一份 `model_catalog.json`。

## 决策 4：包管理用 pnpm

- **背景**：仓库规则写 npm，但 `cross-new` 依赖 `@cross/self-learn: workspace:*`，npm 装包会报 `EUNSUPPORTEDPROTOCOL`；根目录有 `pnpm-workspace.yaml` 与 `pnpm-lock.yaml`，`self-learn/node_modules` 本来就是 pnpm 的软链结构。
- **选择**：在 `self-learn` 下用 `pnpm add`。

## 决策 5：协议类型直接复制，不手写

- **背景**：v1.6.8 起 DeepTutor 前端的协议类型由后端 JSON Schema 生成（`contracts/generated/turn-protocol.ts`），并有配套解析器和传输层。
- **选择**：整套复制到 `src/deeptutor/`，只改 import 路径和两处小扩展（见《移植记录》）。
- **理由**：字段级协议很细（`extra="forbid"`，多一个字段就被拒），手写容易错；传输层的 seq 缺口缓冲、断线续流、命令幂等是现成的。
- **升级 DeepTutor 时**：重新复制这几个文件，注意对比两处本地改动。

## 决策 6：课程 / 掌握度路径怎么用（**已确认：选 B，2026-09-20**）

> 用户确认选 B：老师配置的空间 = Course + 知识库，每个学生一条 Mastery Path。实施分两步：先 chat + 知识库 + 富消息 UI（P3–P5），再接课程与掌握度（P6）。以下为当时的分析。

- **背景**：DeepTutor v1.6 新增了两块和"自习空间"很贴的能力：
  - **Course**：科目容器，含 `instructions`、`default_persona`、大纲、挂载知识库；对话带 `course_id` 会自动继承。
  - **Mastery Path**：确定性的掌握度判定（出题 → 判分 → 掌握度门 → 间隔复习 → 学习地图），这是"chat + 知识库"做不到的。
  - 两者都不区分老师和学生，也没有老师查看学生掌握度的接口；同一条路径同一时间只能有一个会改状态的回合。
- **可选项**：
  - **A. 只用 chat + 知识库**，掌握度、出题、判分由我们自己实现。
  - **B. Course + KB 作为老师配置的空间，每个学生一条 Mastery Path（由同一份模板大纲复制）**，进度隔离，映射关系 `(空间, 学生) → course_id / path_id / session_ids` 存在我们自己这边。
- **建议**：B，分两步走：先做 chat + 知识库 + 富消息 UI（不管选哪条都要），再接掌握度。
- **B 缺什么**（要自习室自己补）：教师端班级视图、老师可配的门阈值（后端写死 0.9，只能靠 `override`）、模板分发、多学生聚合统计。

## 决策 7：知识库怎么划分

- **选择**：每个学习空间一个知识库，名字 `cross-<空间id>`（去掉 DeepTutor 不允许的字符 `< > : " / \\ | ? * # %`）。资源上传或粘贴后由前端在后台送进去，状态写在 `Resource.kbStatus`（`indexing` / `ready` / `failed`）。
- **对话怎么用**：只要空间里有一份资源是 `ready`，`start_turn` 就带 `knowledge_bases: [库名]`；DeepTutor 会先做一次种子检索并发出 `sources` 事件，必要时再调用 `rag` 工具。
- **进入空间时自动补入库**：带 `textContent` 的资源（如粘贴的文本）没有 `kbStatus` 时会重新入库；库被删掉时会忘掉旧的入库状态。**只有原始文件、没有文本的资源，刷新后无法重新入库**（`blob:` 链接已失效）——上传时的一次入库是唯一机会。
- **可入库的扩展名**：pdf、doc(x)、ppt(x)、xls(x)、txt、md、csv、html。DeepTutor 名义上还接受图片、音视频，但那需要额外的 OCR / 语音模型，这里不当作可入库。
- **代价**：知识库是共享的（同一空间的所有学生检索同一个库），符合"老师配置资料、学生使用"的用法。

## 决策 8：agent 预设用 DeepTutor persona，不做 skill

- **背景**：决策 4 原本倾向用 skill。读了 v1.6.8 之后发现有专门的 persona 机制：`start_turn` 带 `persona: <名字>`，后端注入其 markdown。
- **选择**：persona。名字带 `cross-` 前缀（`cross-socratic`、`cross-standard`、`cross-feynman`、`cross-skeptic`、`cross-debater`、`cross-material-guide`），避免与你自己在 DeepTutor 里建的人设重名。
- **实测**：同一个问题「光合作用是什么？」，苏格拉底式先给一句话再反问，标准助教直接给出带公式和表格的完整讲解。

## 决策 9：学习工具怎么产出、怎么展示

- **选择**：每个工具生成的数据形状与现有 viewer 期望的形状一致（卡片 `{front, back}[]`、导图 `{center, branches}`、讲稿 `{time, title, content}[]`、文档 Markdown），viewer 一行不改。
- **产出方式**：卡片 / 导图 / 讲稿 / 时间线 / 总结类走 `chat` + 知识库检索 + "只输出 JSON"；测验类走 `deep_question`；互动页面走 `visualize`。
- **互动页面怎么展示**：生成的完整 HTML 存成 `data:text/html;charset=utf-8,…` 的 URL 放进 `Resource.url`，两个 viewer 原本就是 `<iframe src={url}>`，不用改，刷新后也不会失效（原来的 `blob:` 会失效）。iframe 的 sandbox 没有同源权限，模型生成的脚本碰不到宿主页面。
- **JSON 输出的坑**：模型经常在 JSON 字符串里写没转义的英文双引号（`函数"一一对应"`），`JSON.parse` 直接失败。做法：提示里明确要求"字符串里不要用英文双引号，用「」"；解析失败重试一次；判分这类扁平结构再加宽松兜底解析。
- **一次性生成不占 DeepTutor 历史**：`oneShot.ts` 每次用新连接和新会话，结束后 `DELETE` + `purge`，避免测验生成、判分这些内部调用堆满你 DeepTutor 的会话列表。
- **成本**：`deep_question` 出 3 道题实测约 26 次模型调用、15 万 token；记忆卡片约 9 秒，思维导图约 16 秒，互动页面 1–2 分钟。界面上有"生成中"状态，失败会把原因写进对话。

## 决策 10：判分与错因分析

- **客观题**在前端判：题目和标准答案本来就在前端，没必要请求后端；原来宿主 `/api/chat` 的 `submit_task` 把所有客观题标成正确，已删除。
- **答案编码统一**：单选 = 选项原文，多选 = 选项原文数组，判断 = `'true'|'false'`，填空 = 各空用 `|` 连接。填空比较对 LaTeX 有容错（`$\frac{4}{5}$`、`4/5`、` 4 / 5 ` 视为相同）；答案里含 `\sqrt`、`\pi` 等需要排版的填空题改交 LLM 判。
- **主观题**并行交给 DeepTutor，一题一次调用，返回 0–100 分和评语，60 分及以上算对。
- **错因分析**用主对话（带知识库和当前人设）：把每题的作答和正误拼成一段提示，让导师逐题分析并给复习建议，作为一条流式助手消息出现；这样导师在后续对话里也记得这次测验。
- 已知：`deep_question` 的题干里会带 `[source-1]` 这种检索标记，适配层统一清掉。

## 决策 11：AI 引导模式 = 一条掌握度路径

- **背景**：原来引导模式的学习路径是写死的 5 个节点，检查点和过渡卡片也是固定剧本，且从不随学习更新。
- **选择**：进入引导模式且知识库有可用资料时，自动 `draft` → `create` 一条掌握度路径（约 30 秒），模块变成路径节点，`next.module_id` 是"当前"节点；对话绑定到这条路径（`workspace_mode: 'mastery_path'`、`mastery_path_id`、`mastery_session_mode: 'study'`），用它专属的会话；每回合结束刷新一次学习地图。
- **草稿接口没有语言参数**，输出默认是英文；在 `goal` 里写"请…全部使用简体中文"可以稳定得到中文。
- **导师出题不是 `ask_user`**：它发 `tool_result`，卡片在 `tool_metadata.mastery_question`，**出题会结束当前回合**；学生作答要发新回合并带 `mastery_answer`；判分在下一回合的 `tool_metadata.mastery_grade.result` 里。
- **学习前的摸底是 `ask_user`**：回合暂停成 `waiting_input`，`tool_metadata.ask_user` 里是最多 3 个问题，选项是 `{label, description}` 对象（不是字符串），还有 `header`、`multi_select`；用 `submit_user_reply` 带 `answers:[{questionId, text}]` 回答，**同一个回合**继续。界面没处理这个状态时，回合会一直挂着、输入框一直禁用。
- **每个学生一条路径**：同一路径同一时间只允许一个会改状态的回合。目前是每个空间一条，多学生要按 (空间, 学生) 各建。

## 决策 12：资源查看器与刷新后的原文件

- **现象**：全屏能看 PDF，缩小成小窗后显示 "This page has been blocked by Chrome"。
- **根因**：全屏弹窗对上传文件有专门的渲染（PDF 用不带沙箱的 iframe、图片、docx、音视频），小窗把所有有链接的资源都当"互动网页"放进 `sandbox` iframe；Chrome 内置的 PDF 查看器在沙箱 iframe 里会被拦截。另外「缩小 / 放大」两个方向转换资源对象时都丢了 `fileType` 和 `path`。
- **修法**：把 `UploadedFileViewer` 抽成共用组件，两个查看器都用；转换时带上 `fileType` / `path`。
- **刷新后的原文件**：上传文件的 `blob:` 链接刷新即失效。资源已入库的话，点开时先探一下链接是否还活着，失效就改用 DeepTutor 知识库保存的原文件（`GET /api/knowledge-bases/{kb}/files/{name}`，返回 `application/pdf` + `content-disposition: inline`，可以直接放进 iframe）。

## 决策 13：学生进度与老师状态分开存

- **现象**：老师和学生在同一浏览器里看到同一份聊天记录，学生还会接着老师的 DeepTutor 会话往下聊，也共用同一条掌握度路径。原因是这些状态只按空间 id 存（`self-study:wb:<空间id>:…`）。
- **选择**：学生端（`mode="student"`）的进度类状态改存到 `self-study:wb:<空间id>:student:…`：聊天记录、两个 DeepTutor 会话、掌握度路径、学习路径、当前节点、任务记录、已完成任务、学习时长。老师生成的资源、任务和工具配置仍按空间共享。
- **仍然做不到的**：没有账号体系，**同一浏览器里的所有学生共用一份**；空间配置、发布快照也只在浏览器 localStorage 里，学生端页面只传了 `spaceId`，换一个浏览器就看不到这个空间。所以「老师发布 → 学生在另一台设备学习」需要一个服务端来存空间、发布快照和每个学生的进度，这不是 DeepTutor 的能力，需要在 `cross-new` 里自建。
