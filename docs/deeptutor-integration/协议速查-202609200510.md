## 2. 客户端命令

每条命令必须带 `protocol_version:"2.0"`；所有命令模型 `extra="forbid"`，多带任何未知字段只得到笼统的 `invalid_command`。`UnifiedTurnClient.send()` 会自动补版本号。

| type | 关键字段 | 备注 |
|---|---|---|
| `start_turn` | `content`、`session_id`、`capability`、`tools`、`knowledge_bases`、`language`、`config`、`attachments`、`persona`、`skills`、`llm_selection`、`course_id`、`mastery_*` … | 完整字段见契约文件 |
| `subscribe_turn` | `turn_id`、`after_seq` | 回放并续订 |
| `subscribe_session` | `session_id`、`after_seq` | 订阅该会话当前活跃回合 |
| `resume_from` | `turn_id`、`seq` | 注意字段叫 `seq` |
| `cancel_turn` | `turn_id`、`command_id` | `command_id` 必填，客户端生成 UUID，用于幂等 |
| `submit_user_reply` | `turn_id`、`command_id`、`text` 或 `answers[{questionId,text}]` | 只用于真正的 `waiting_input`（ask_user） |
| `user_input` | `turn_id`、`command_id`、`content` | 向运行中的回合追加输入 |
| `regenerate` | `session_id`、`overrides` | |
| `unsubscribe` / `check_active_turn` / `ping` | | |

`start_turn` 的约定：

- **`session_id` 首轮传 `null`**，从 `session` 事件里取服务端分配的 id。传一个不存在的 id 也不会被采用（服务端会新建随机 id）。
- **同一会话同一时间只允许一个进行中的回合**；冲突时收到 `protocol_error{error_code:"start_turn_rejected", retryable:true}`，此时**不会有 `done`**。
- **`tools` 传 `[]`** 表示不用可选工具；传 `null` 会回填成用户在设置里启用的那批（含联网搜索、推理等）。`rag`、`ask_user`、`write_memory` 等是自动挂载的，`tools` 关不掉。
- **`knowledge_bases` 传 KB 的 name**，不是列表接口返回的 `id`（`admin:kb:xxx`）。
- `deep_research` 的 `config.mode`、`config.depth` 必填；`chat` / `deep_solve` 的 `config` 必须是 `{}`。
- 附件的 `base64` 是裸串，不能带 `data:` 前缀；服务端 WS 帧上限约 43MB，单文件 20MB，总量 25MB。

## 3. 服务端帧

每帧带 `protocol_version:"2.0"`。除下面 5 类帧外，无其他。

| 帧 | 说明 |
|---|---|
| **StreamEvent** | 15 种 `type`，见下 |
| `command_ack` | `{command_id, command_type, accepted, turn_id, error_code, message}` |
| `protocol_error` | `{error_code, message, retryable, session_id, turn_id}` |
| `active_turn_info` | `{turn_id, status, owner_id}` |
| `pong` | |

**StreamEvent**：`{type, source, stage, content, metadata, session_id, turn_id, seq, timestamp}`，`seq` 在单个回合内从 1 连续递增。

`type` 取值：`stage_start`、`stage_end`、`thinking`、`observation`、`content`、`tool_call`、`tool_result`、`progress`、`sources`、`result`、`error`、`session`、`session_meta`、`wait_for_input`（**从未被产出，可忽略**）、`done`。

一轮 chat 的实测顺序（无工具）：

```
session > stage_start > progress > thinking* > content* > progress > stage_end > result > done
```

（`*` 表示增量分片。实测「1+1」：`thinking` 12 片、`content` 5 片，首个 `content` 约在 7.6 秒到达。）

## 4. 语义要点（容易踩坑）

1. **回答是增量流**。累加规则（`src/deeptutor/lib/stream.ts`）：
   - 没有 `metadata.call_id` 的 `content` 一律算答案；
   - 有 `call_id` 的，只有 `call_kind ∈ {llm_final_response, agent_loop_round}` 才算；
   - 之后若收到 `progress` 且 `metadata.trace_kind=="call_status" && call_state=="complete" && call_role=="narration" && answer_visible!==true`，要**追溯剔除**该 `call_id` 的文本（`recomputeAnswerContent`）。
2. **`done` 不是最后一个事件**：标题的 `session_meta` 会在 `done` 之后到达。`DeepTutorChat` 在 `done` 时结束该回合，并过滤已结束回合的迟到事件，避免污染下一轮。
3. **`error` 事件不等于失败**：capability 内部异常时会发 `error`，随后的 `done.status` 仍可能是 `completed`。终结型错误看 `metadata.turn_terminal`。取消时收到的是 `error`（内容 `Turn cancelled`）+ `done{status:"cancelled"}`（实测）。
4. **工具自带元数据在 `metadata.tool_metadata` 下**，读顶层会静默拿到空值。`ask_user`、`mastery_question`、`mastery_grade`、`course_handoff` 都在这里。
5. **`cost_summary` 位置**：`result.metadata.metadata.cost_summary`（`{total_cost_usd, total_tokens, total_calls, prompt_tokens, completion_tokens}`）。
6. **mastery 出题会结束当前回合**，答案要发新的 `start_turn` 并带 `mastery_answer`，不是 `submit_user_reply`。
7. 请求被拒时只发 `protocol_error`，客户端如果只处理 StreamEvent 会一直等下去，所以 `UnifiedTurnClient` 增加了 `onControlFrame`。

## 5. 认证与安全

- 默认免认证：`GET /api/auth/status` → `{enabled:false, is_admin:true, user_id:"local-admin"}`。
- CORS 认证关闭时放行任意 Origin 且允许凭据；WS 不校验 Origin。
- `GET /api/settings/catalog` 现在把 `api_key` 打码成 `"***"`（v1.4.2 是明文）。
- 单用户模式下所有会话、记忆、笔记本、课程共享；`GET /api/sessions` 返回全部会话。多学生隔离要自己维护 `(空间, 学生) → session_id / path_id` 的映射。

## 6. 能力（capability）与工具

`GET /api/capabilities/registered` 实测 11 个：`chat`、`deep_solve`、`deep_question`、`deep_research`、`visualize`、`math_animator`、`ask_questions`、`mastery_path`、`course_study`、`immersive_reading`、`immersive_watching`。旧的 `auto` 已不存在，改为 `auto_route` 标志。

可开关工具共 7 个：`brainstorm`、`web_search`、`reason`、`paper_search`、`geogebra_analysis`、`imagegen`、`videogen`。旧名 `code_execution` 现在是 `exec`（不在可开关列表里）。

## 7. 课程与掌握度（尚未接入）

- **Course**：学习者自己的科目容器（`instructions`、`default_persona`、`syllabus`、挂载资源，资源类型含知识库）。对话时 `start_turn` 带 `course_id`，会自动继承课程的知识库、人设并注入课程约定。REST：`/api/courses...`。
- **Mastery Path**：话题 → 模块 → 知识点，有确定性的掌握度门（`memory`/`procedure` 近期正确率 ≥ 0.9；`concept`/`design` 由 LLM 做 Feynman 式定性判定）、间隔复习、学习地图。对话带 `workspace_mode:"mastery_path"`、`mastery_path_id`、`mastery_session_mode:"outline"|"study"|"review"`。REST：`/api/mastery-paths/...`，事件订阅 `WS /ws/mastery-paths`。
- 都**不区分老师和学生**，也没有老师查看学生掌握度的接口。同一条路径同一时间只能有一个会改状态的回合，所以**每个学生要有自己的一条路径**。
